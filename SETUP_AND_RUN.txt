FIRST-TIME SETUP — run these steps once
================================================================

--- Step 1: Database ----------------------------------------

1a. Open Docker Desktop from the Start menu.
    Wait until the whale icon in the system tray is steady
    (not animating). This takes about 30 seconds.

1b. Open a terminal, navigate to the SHIELD root folder:

        cd "d:\SCHOLARSHIPS\My Items\Degree Project\FYP\SHIELD"

1c. Start the PostgreSQL container:

        docker compose up -d

    First time: Docker downloads postgres:15-alpine (~100 MB).
    Subsequent runs: starts instantly from cache.

1d. Confirm it is healthy (wait ~10 seconds after starting):

        docker compose ps

    You should see shield_postgres with STATUS "healthy".
    If it shows "starting", wait a few more seconds and retry.

--- Step 2: Backend -----------------------------------------

2a. Navigate to the backend folder:

        cd "d:\SCHOLARSHIPS\My Items\Degree Project\FYP\SHIELD\backend"

2b. Create a virtual environment (first time only):

        python -m venv venv

2c. Activate the virtual environment:

        venv\Scripts\activate

    Your prompt will show (venv) at the start.

2d. Install all Python dependencies (first time only):

        pip install -r requirements.txt

    This installs: fastapi, uvicorn, xgboost, shap, sqlalchemy,
                   asyncpg, groq, pandas, numpy, joblib, etc.

2e. Create your .env file (first time only):

        copy .env.example .env

2f. Open backend\.env in a text editor and add your keys:

    ── Required: Database URL ──────────────────────────────────
    This connects the backend to the Docker PostgreSQL container.
    The credentials match docker-compose.yml exactly.

        DATABASE_URL=postgresql+asyncpg://shield:shield@localhost:5400/shield_db

    Port 5400 is used because 5432 is taken by a local PostgreSQL
    installation, and Windows reserves ports 5433–5532 for Hyper-V/WSL.
    Docker maps its internal 5432 to your machine's 5400 — no conflict.

    ── Optional: Groq API key (AI advisory) ────────────────────
    Get a free key at https://console.groq.com (no billing needed)

        GROQ_API_KEY=your_key_here

    If either key is missing, that feature is disabled gracefully
    and the app still works.
    ─────────────────────────────────────────────────────────────

    then python run.py

--- Step 3: Frontend ----------------------------------------

3a. Open a NEW terminal. Navigate to the frontend folder:

        cd "d:\SCHOLARSHIPS\My Items\Degree Project\FYP\SHIELD\frontend"

3b. Install Node dependencies (first time only):

        npm install

    This may take a minute. Wait for it to complete.


================================================================
RUNNING THE APP — do this every time
================================================================

You need three things running at the same time.
Open three separate terminal windows.

------------------------------------------------------------
TERMINAL 1 — Database
------------------------------------------------------------

1. Open Docker Desktop and wait for it to be ready
   (whale icon steady in system tray).

2. Navigate to the SHIELD root folder:

       cd "d:\SCHOLARSHIPS\My Items\Degree Project\FYP\SHIELD"

3. Start the database:

       docker compose up -d

4. Verify it is healthy:

       docker compose ps

   STATUS should show "healthy" before you start the backend.

   If the container is already running from a previous session,
   docker compose up -d is safe to run again — it does nothing.

------------------------------------------------------------
TERMINAL 2 — Backend (FastAPI)
------------------------------------------------------------

1. Navigate to the backend folder:

       cd "d:\SCHOLARSHIPS\My Items\Degree Project\FYP\SHIELD\backend"

2. Activate the virtual environment:

       venv\Scripts\activate

3. Start the API server:

       python run.py

   You should see these lines on startup (order may vary):

       INFO  Loading XGBoost model ...
       INFO  Building SHAP TreeExplainer ...
       INFO  Initialising Groq advisory engine ...
       INFO  Database ready — evaluations table confirmed.
       INFO  SHIELD backend ready.

   API runs at:          http://localhost:8000
   Interactive API docs: http://localhost:8000/docs

   If you see "Application startup failed" check:
     - Is Docker Desktop open? (whale icon in tray)
     - Did you run docker compose up -d first?
     - Is DATABASE_URL correct in backend\.env?

------------------------------------------------------------
TERMINAL 3 — Frontend (Next.js)
------------------------------------------------------------

1. Navigate to the frontend folder:

       cd "d:\SCHOLARSHIPS\My Items\Degree Project\FYP\SHIELD\frontend"

2. Start the development server:

       npm run dev

   Dashboard:  http://localhost:3000
   Logs page:  http://localhost:3000/logs

   Open http://localhost:3000 in your browser.

------------------------------------------------------------
STOPPING
------------------------------------------------------------

   Backend + Frontend : Ctrl + C in each terminal

   Database           : In the SHIELD root terminal:
                            docker compose down

   To wipe all saved data and start the database fresh:
                            docker compose down -v

================================================================
TROUBLESHOOTING
================================================================

Problem : "Application startup failed" / asyncpg password error
Fix     : Docker Desktop is not running or the container is not
          started. Follow these steps in order:
            1. Open Docker Desktop, wait for whale icon to settle
            2. cd "...\SHIELD"
            3. docker compose up -d
            4. docker compose ps  — confirm STATUS is "healthy"
            5. Restart the backend: python run.py

Problem : docker compose ps shows "starting" not "healthy"
Fix     : The container needs more time. Wait 15 seconds and
          run docker compose ps again. If it never becomes
          healthy: docker compose logs db

Problem : "docker is not recognized"
Fix     : Docker Desktop is not installed or not on PATH.
          Install from https://www.docker.com/products/docker-desktop
          then restart your terminal.

Problem : Port binding error / "access permissions" on Docker start
Fix     : Windows (Hyper-V/WSL) reserves large port ranges including
          5433-5532. The docker-compose.yml is already set to use
          port 5400 which is outside all reserved ranges. If you still
          see this error, check excluded ranges with:
              netsh int ipv4 show excludedportrange protocol=tcp
          Then pick any port not in those ranges and update both
          docker-compose.yml and DATABASE_URL in backend\.env.

Problem : Port 5432 already in use (local PostgreSQL conflict)
Fix     : Your local PostgreSQL owns 5432. The docker-compose.yml
          and DATABASE_URL are already set to port 5400 to avoid
          this. If you still see the error confirm backend\.env has:
              DATABASE_URL=postgresql+asyncpg://shield:shield@localhost:5400/shield_db

Problem : /logs page shows "Could not load logs" (503)
Fix     : DATABASE_URL is not set in backend\.env, or Docker is
          not running. Check: docker compose ps

Problem : "No module named 'groq'"
Fix     : Run inside the activated venv:
              pip install "groq>=1.7.0"

Problem : "python is not recognized"
Fix     : Python is not on PATH. Reinstall Python and check
          "Add Python to PATH" during setup.

Problem : venv\Scripts\activate not recognised
Fix     : You are not inside the backend/ folder. Run:
              cd "...\SHIELD\backend"
          then activate.

Problem : "npm is not recognized"
Fix     : Node.js is not installed. Download from https://nodejs.org/

Problem : Frontend shows "Failed to fetch" or API errors
Fix     : The backend is not running. Start Terminal 2 first.
          Check: http://localhost:8000/health

Problem : Backend crashes — model file not found
Fix     : Confirm xgb_shield_model.joblib is in SHIELD/model/
          Check MODEL_PATH in backend\.env:
              MODEL_PATH=../model/xgb_shield_model.joblib

Problem : Port 8000 already in use
Fix     : Edit backend\.env:  PORT=8001
          Edit frontend\.env.local:
              NEXT_PUBLIC_API_URL=http://localhost:8001

Problem : Port 3000 already in use
Fix     : Next.js auto-tries 3001, 3002 etc. Check terminal output.

Problem : SHAP slow on first prediction
Fix     : Normal. TreeExplainer is built once at startup.
          First call takes a few seconds; subsequent calls are fast.


================================================================
API QUICK REFERENCE (v1.0.2)
================================================================

GET  /health
     → Model, explainer, and Groq status

GET  /features
     → 20 feature labels, medians, preset profiles

POST /predict
     → Body:
         {
           "meta": {
             "company_name": "Syarikat ABC Sdn Bhd",
             "ssm_number":   "1234567-A",
             "loan_amount":  500000,
             "evaluator":    "analyst"
           },
           "financials": {
             "roa_a": 0.586,
             "roa_b": 0.588,
             ... (20 float fields, normalised 0-1)
           }
         }
     → Returns: probability, classification, SHAP values,
                advisory report

GET  /logs?limit=200
     → All past evaluations, newest first
     → Requires DATABASE_URL and Docker to be running

Full interactive docs: http://localhost:8000/docs
